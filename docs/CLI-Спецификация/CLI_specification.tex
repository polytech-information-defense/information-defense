\section{Спецификация командного интерфейса управления (CLI)}

\subsection{Общие принципы работы}
Командный интерфейс (CLI) предназначен для локального (через консоль) и удаленного (по протоколу SSH согласно ДСТ-07) управления ПО МЭ. Взаимодействие осуществляется в интерактивной оболочке. Синтаксис команд имеет иерархическую структуру:
\begin{center}
\texttt{<объект> <действие> [аргументы]}
\end{center}

При работе CLI соблюдаются следующие требования спецификации:
\begin{itemize}
    \item \textbf{Аутентификация (ДСТ-01):} Доступ к оболочке возможен только после ввода логина и пароля.
    \item \textbf{Разграничение прав (ДСТ-03):} Функции разделены на уровни ЧЗ (Чтение/Запись) и ТЧ (Только чтение). Попытка вызова команды уровня ЧЗ пользователем с правами ТЧ отклоняется с выдачей сообщения и регистрацией события с кодом 106 (согласно Приложению А).
    \item \textbf{Валидация данных (НДЖ-04):} Все вводимые администратором команды и их аргументы должны проходить проверку на корректность. Для команд проверяется правильность синтаксиса, для передаваемых данных — соответствие форматам (IP-адреса, MAC-адреса) и допустимым диапазонам значений (номера портов, типы ICMP). Некорректные команды и значения отклоняются с выдачей сообщения об ошибке без изменения состояния ПО МЭ.
    \item \textbf{Подтверждение операций (УПР-15):} Опасные операции (перезагрузка, очистка логов, удаление учетных записей) требуют интерактивного подтверждения вводом \texttt{y} или \texttt{n}.
\end{itemize}

\subsection{Работа в режиме аварийной поддержки (ЦЛС-05)}

При выявлении нарушения целостности хотя бы одного контролируемого файла (ЦЛС-04) ПО МЭ блокирует весь обрабатываемый трафик на всех интерфейсах, регистрирует событие с указанием файлов с нарушенной целостностью и переходит в режим аварийной поддержки. 

В данном режиме доступно только локальное управление через CLI после аутентификации администратора с правами ЧЗ. Перечень доступных команд и их аргументов приведен в таблице \ref{tab:emergency_cmds}.

\subsection{Примеры выполнения команд}

\textbf{Пример 1. Добавление правила (Права ЧЗ):}
\begin{verbatim}
admin@firewall> rule add --num=10 --in=port1 --src-ip=192.168.1.0/24 
--proto=tcp --dst-port=80 --action=pass --comment="Allow Web"
[УСПЕХ] Код: 300 | Описание: Добавление правила
\end{verbatim}

\textbf{Пример 2. Отказ в доступе (Недостаточно прав):}
\begin{verbatim}
user_ro@firewall> interface set --name=port1 --state=down
[ОШИБКА] Код: 106 | Описание: Отказ в выполнении функции | Причина: 
Недостаточно прав (требуется уровень ЧЗ)
\end{verbatim}

\textbf{Пример 3. Понижение прав при повторном входе (ДСТ-05):}
\begin{verbatim}
admin2@firewall> login
Пароль: ********
[УСПЕХ] Код: 105 | Описание: Понижение прав сеанса до «только чтение»
\end{verbatim}

\textbf{Пример 4. Подтверждение опасной операции (УПР-15):}
\begin{verbatim}
admin@firewall> system reboot
[ВНИМАНИЕ] Вы собираетесь перезагрузить изделие. Вы уверены? (y/n): y
[УСПЕХ] Код: 202 | Описание: Перезагрузка изделия
\end{verbatim}

\textbf{Пример 5. Проверка корректности ввода (НДЖ-04):}
\begin{verbatim}
admin@firewall> rule add --num=5 --dst-port=99999 --action=drop
[ОШИБКА] Код: 300 | Описание: Добавление правила | Причина: 
Некорректное значение аргумента '--dst-port'. Допустимый диапазон: 
1-65535
\end{verbatim}
